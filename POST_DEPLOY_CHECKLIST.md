# Чеклист после деплоя — пошагово для начинающих

Этот файл описывает, что делать сразу после развёртывания проекта в ephemeral cloud (например, Cursor Cloud или другой VM без постоянного диска).

---

## Часть 1. Подготовка (один раз)

### Шаг 1.1. Скопировать готовый конфиг

В корне проекта выполни:

```
cp .env.cloud.ready .env.cloud
```

**Что должно получиться:** появится файл `.env.cloud`, идентичный `.env.cloud.ready`. Это твой рабочий конфиг. Его не коммитят в git.

---

### Шаг 1.2. Открыть `.env.cloud` и заполнить два поля

Открой файл `.env.cloud` в редакторе и замени пустые значения:

**1) TG_BOT_TOKEN**

Где взять: Telegram → @BotFather → /newbot или /mybots → скопируй токен (например, `123456789:ABCdef...`).

Вставь его в кавычки:

```
TG_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
```

**2) TG_BOT_OWNER_CHAT_ID**

Где взять:
- Напиши боту любое сообщение (например, `/start`).
- Открой в браузере: `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
- В ответе найди `"chat":{"id": 123456789}` — это твой chat_id.

Вставь только число:

```
TG_BOT_OWNER_CHAT_ID="123456789"
```

**Про WEBHOOK_APP_URL_ROOT:** оставь пустым. Для первого запуска используется polling, публичный URL не нужен.

---

### Шаг 1.3. Установить зависимости (bootstrap)

Выполни:

```
bash ./cloud_startup.sh
```

**Что должно получиться:**
- Установится Poetry (если ещё нет)
- Установятся все Python-зависимости (это займёт 1–3 минуты)
- В конце увидишь строки типа `Poetry: ...` и `FFmpeg: ...`
- Ошибок быть не должно

---

### Шаг 1.4. Проверить окружение (preflight)

Выполни:

```
make cloud_preflight
```

**Что должно получиться:**
- Строка `BOT_MODE: scdlbot`
- Строка `Runtime configuration validation completed`
- Строка `All downloader CLI tools are available`
- Строка `Cloud preflight checks passed`
- Ошибок быть не должно

**Если ошибка:** проверь, что `TG_BOT_TOKEN` и `TG_BOT_OWNER_CHAT_ID` заполнены в `.env.cloud`.

---

### Шаг 1.5. Сухой прогон (проверка без запуска бота)

Выполни:

```
make cloud_dry_run
```

**Что должно получиться:**
- Строка `dry_run_ok:scdlbot`
- Команда завершится быстро, бот не запустится

**Если ошибка:** возможно, проблемы с окружением. Запусти снова `bash ./cloud_startup.sh` и проверь FFmpeg: `ffmpeg -version`.

---

## Часть 2. Запуск бота

### Шаг 2.1. Запустить бота

Выполни:

```
make cloud_run
```

**Что должно получиться:**
- Появятся строки логов, например:
  - `ephemeral storage mode active`
  - `config validation passed`
  - `startup mode=polling`
  - `healthcheck server started host=0.0.0.0 port=8080`
  - `Application started`
- Бот продолжит работать (процесс не завершится)

**Как остановить:** нажми `Ctrl+C` в терминале.

---

### Шаг 2.2. Проверить health endpoint

В **другом** терминале (или в браузере, если доступен localhost) выполни:

```
curl http://127.0.0.1:8080/healthz
```

**Что должно получиться:**
- Ответ `OK` или похожий

**Ещё можно проверить:**

```
curl http://127.0.0.1:8080/readyz
```

---

### Шаг 2.3. Проверить бота в Telegram

1. Открой Telegram.
2. Найди своего бота (по username из @BotFather).
3. Нажми **Start** или отправь команду `/start`.
4. Бот должен ответить приветствием.

**Дополнительная проверка:** отправь боту ссылку на трек (SoundCloud, YouTube, Bandcamp и т.п.). Бот должен начать загрузку и прислать аудиофайл.

---

## Часть 3. Если бот не стартовал

### Симптом: `TG_BOT_TOKEN is required`

**Причина:** токен не заполнен или пустой.

**Что сделать:** открой `.env.cloud`, вставь реальный токен в `TG_BOT_TOKEN="..."`, сохрани файл и снова запусти `make cloud_run`.

---

### Симптом: ошибка при `getMe` или `getUpdates`

**Причина:** токен неверный или отозван.

**Что сделать:** проверь токен в @BotFather. Если бот был удалён или токен отозван — создай нового бота и получи новый токен.

---

### Симптом: `ffmpeg is missing in PATH`

**Причина:** FFmpeg не установлен.

**Что сделать:** установи FFmpeg (на Ubuntu/Debian: `sudo apt install ffmpeg`). В Cursor Cloud FFmpeg обычно уже есть.

---

### Симптом: бот запустился, но не отвечает в Telegram

**Причина:** возможны ограничения сети или неверный chat_id.

**Что сделать:**
1. Убедись, что интернет доступен с сервера.
2. Проверь `TG_BOT_OWNER_CHAT_ID`: снова напиши боту `/start`, открой `getUpdates` и свери chat_id.
3. Посмотри логи бота — там могут быть подсказки.

---

### Симптом: `WEBHOOK_APP_URL_ROOT is required when WEBHOOK_ENABLE=1`

**Причина:** включён webhook, но не задан публичный URL.

**Что сделать:** для первого запуска отключи webhook. В `.env.cloud` поставь `WEBHOOK_ENABLE="0"`. Либо заполни `WEBHOOK_APP_URL_ROOT="https://твой-домен.com"` и настрой webhook отдельно (см. раздел ниже).

---

## Часть 4. Переход на Webhook (необязательно)

Webhook нужен, когда бот работает за reverse proxy (nginx, Caddy и т.п.) или на платформах вроде Render, где polling неудобен.

**Что дополнительно заполнить:**
1. `WEBHOOK_ENABLE="1"`
2. `WEBHOOK_APP_URL_ROOT="https://твой-публичный-домен.com"` — без слэша в конце
3. `WEBHOOK_SECRET_TOKEN` — случайная строка для защиты (можно сгенерировать: `openssl rand -hex 24`)

**Что настроить на сервере:**
- Порт 5000 должен быть доступен извне (или проксирован на 5000).
- HTTPS обязателен для webhook Telegram.

**Когда использовать:** если у тебя уже есть домен, SSL и reverse proxy. Для первого запуска и локальной разработки используй polling (`WEBHOOK_ENABLE="0"`).
